Design of record & what changed renewed 2026-10-11 · updated 2026-10-12

mihomo dashboard — metacubexd →

  • One owner per job: mihomo decides policy (rules, which upstream proxy, DNS policy); HypoMux decides which adapter each dial leaves by — every dial, direct included. Chain apps/system proxy → mihomo → HypoMux → the adapters, system proxy on both components, no TUN anywhere. Canonical statement: docs\HYPOMUX-DISTRIBUTION.md.
  • 2026-10-12 additions: the two DeepSeek rules are raw DIRECT (owner: "the deepseek and the deepseekapi must use direct and not proxy, otherwise we cannot visit deepseek here") — with loop protection, the only rules that bypass the dispatch hop; a RepoHygiene test now pins them. The Aliyun box gained protocols (AnyTLS 8080/tcp, TUIC 18240/udp, Trojan-TLS 18240/tcp; reality moved to 0.0.0.0:1080 direct, its steal target fixed from www.microsoft.com — which never completed the mirrored handshake — to www.bing.com, and the orphan socat relay retired) and was measured from this PC: anytls 5.24 MB/s · http-3128 5.26 · reality 4.78 · trojan 4.42 · ss 2.06 — ss is the slowest of the TCP family, anytls the candidate to promote into the mix; the new outbounds are not yet in the live config (bench rig: state\aliyun-bench). The manual trio is start-all.bat / stop-all.bat / fixall.bat, and the live config's mixed-port was restored to 7897 after the bench session (a leftover had it on 17897, colliding with a bench listener).
  • HypoMux dispatches everything (owner, 2026-10-11 — the day's third revision): direct traffic leaves through the new DISPATCH group = fallback [hypomux, DIRECT], health-checked on https://www.baidu.com (expected 200, interval: 30, timeout: 5000, lazy: false). hypomux there is the SOCKS5 listener used as a plain dialer: mihomo names the destination, HypoMux opens the socket from the adapter it picks. The DIRECT member is deliberate — HypoMux is now a hop for everything, so if its engine stops the machine must not lose the internet: the group degrades to the OS route. Only loopback (127.0.0.0/8), the private ranges and the two DeepSeek rules stay raw DIRECT — loopback because a NIC-bound socket cannot reach 127.0.0.1, where HypoMux (10800) and the ssh tunnel (1080) live, and DeepSeek by owner order (2026-10-12: through any proxy it is unreachable here).
  • The proxy path is a 911-first 4:1 mix (owner, 2026-10-11 — the day's fourth change: "for proxy, we can use our 911 connect first and then use the aliyun server proxy (4:1), all through hypomux dispatch"). AUTO — the group every proxy rule resolves through, RULE-SET,clashmi-911 included — is a load-balance on round-robin with five members: four 911 exits chosen by filter: — 香港|HK2022|AT (the owner's main 911 node, 80 ms, fastest of all 49 measured), 台湾|TW2035|AT (112 ms), 新加坡|SG2034|AT (115 ms), 马来西亚|MY2032|AT (118 ms) — plus aliyun-native as the "1" share. lazy: false (it was lazy: true), interval: 60, health check on google/generate_204. Round-robin and not consistent-hashing (hashing pins a destination to ONE member); the ratio is by member count because mihomo groups have no weights; and the four are selected by regex over node names, not listed under proxies:, because a name that disappears would make the whole config invalid — the trap that retired the per-NIC rings (a rename therefore silently shrinks the ratio). Measured over 20 connections: HK 5 · TW 4 · SG 4 · aliyun-native 4 · MY 3 — exactly 4 paid : 1 Aliyun, so 4 of every 5 proxied connections now spend the metered 911 plan. History kept: AUTO used to be fallback [HYPOMUX-PATH] + use: [clashmi] — free-first, and it was the day's second and third decisions that narrowed the proxied set rather than reordering it.
  • The mix's own trap — and the correction to "HYPOMUX-PATH is the free path". The first version used HYPOMUX-PATH as the Aliyun member and sent 10 of 10 test connections to paid nodes: a silent 0-in-5 Aliyun share. HYPOMUX-PATH = fallback [hy2-upstream, aliyun-native] can never be healthy through HypoMux (hysteria2 is QUIC, the hop is TCP SOCKS), so the group reported itself unhealthy and a load-balance skips unhealthy members. Measured then: aliyun-native 366 ms alive, hy2-upstream failed, HYPOMUX-PATH alive=false. The mix names aliyun-native directly now; HYPOMUX-PATH is still defined but no longer referenced by any policy.
  • The dial is what gets distributed: aliyun-native (ss) and hy2-upstream (hysteria2) carry dialer-proxy: hypomux, so every member of the mix still leaves by an adapter HypoMux picks. HYPOMUX-PATH resolves to aliyun-native (hysteria2 cannot cross the TCP SOCKS hop) but nothing routes through that group any more.
  • Only what a rule names is proxied — the catch-all is MATCH,DISPATCH (owner, 2026-10-11; it was MATCH,DIRECT earlier that day, and MATCH,HYPOMUX-PATH before that — the order is MATCH,LOCAL → MATCH,HYPOMUX-PATH → MATCH,DIRECT → MATCH,DISPATCH). The proxy set is our own rules, the learner's escalations, and the 911 subscription's own must-proxy list, lifted out of that subscription by tools\Update-Clashmi911Rules.ps1 into rule-provider clashmi-911 (354 entries, runtime\rules\clashmi-911.yaml) and referenced as RULE-SET,clashmi-911,AUTO — its 197 DIRECT entries and its MATCH,OpenConnectUs911 tail are dropped on purpose. Measured in mihomo's own log: www.163.com → match Match using DISPATCH[hypomux], futuhk.com → RuleSet(clashmi-911) using AUTO[aliyun-native], www.youtube.com → AUTO[aliyun-native] — those two AUTO[aliyun-native] readings are from before the 4:1 mix, when the group was that one member; under the mix the same rule shows whichever of the five round-robin picked. Under MATCH,DIRECT the same class of host read www.speedtest.net → match Match using DIRECT — kept as that revision's record.
  • Microsoft Store + Windows Update are pinned DISPATCH (they were pinned DIRECT), above the auto-learner and above the 911 rule set (first match wins), with DOMAIN,copilot.microsoft.com,AUTO as the deliberate exception placed first — and after the 4:1 mix that exception lands on one of five members, not on the free path by construction. Measured reason: the Store downloads from a domestic CDN at ~17.8 MB/s. Measured result: displaycatalog.mp.microsoft.com → DomainSuffix(microsoft.com) using DISPATCH[hypomux], download.windowsupdate.com → DomainSuffix(windowsupdate.com) using DISPATCH[hypomux], and api.deepseek.com read DomainSuffix(deepseek.com) using DISPATCH[hypomux] until 2026-10-12, when the owner ordered DeepSeek back to raw DIRECT (it reads using DIRECT now). AUTO's health-check interval is 60 s (was 120 s) so a post-reload unhealthy window cannot park traffic on a paid node for two minutes — the interval lesson survives the mix, but lazy: true does not: the mix runs lazy: false, because a load-balance needs live health data to skip a dead exit.
  • Dispatch proof: hypomux-engine (pid 23188) held 25 sockets to non-proxy destinations, split 19 via 10.90.126.33 / 6 via 192.168.1.100 — ordinary direct traffic genuinely leaving by both NICs under HypoMux's choice — and the same process owned all the upstream sockets (Aliyun 5, paid 112.91.92.129 = 50) with mihomo holding zero on those hosts. Tested through its SOCKS5 on 10800, bypassing mihomo, HypoMux dialled gstatic 204, example.com 200 (6/6 retries clean), microsoft.com 200, proof.ovh.net 200, baidu 200, cloudflare.com 200, github.com 200; wikipedia.org answered 403 through the hop while the plain OS route timed out. No measurable latency cost (baidu 0.204 s vs 0.221 s); one example.com timeout was a transient and did not reproduce. Honest tradeoffs: HypoMux is now a single point of failure for the whole machine (direct traffic survives only via the group's DIRECT fallback, proxied traffic fails), per-connection failures are not retried by mihomo (the fallback is group-level and health-check based), and the auto-learner matters more — its task is currently Disabled (docs\TODO.md P0d).
  • NIC selection is human-controlled in the HypoMux GUI: its engine is a child of hypomux.exe driven over the GUI's stdio channel, there is no control API, and no script in this repo drives it. (2026-10-12: the protocol the GUI speaks — v1, with live engine.scheduling and telemetry — is documented from the source; a gui-vs-agent ownership design is section 12 of the design review, still the owner's call.)
  • Retired 2026-10-11 — the switch ran for real: the generated per-NIC outbounds, the HY2LB/DIRECT-LB/MIX rings, and the AdapterMonitor watcher that rewrote them are gone from the live config and stopped (task Disabled, zero Watch-Adapters processes). hypomux-distribution.ps1 (no arguments; -Check / -Restore / -DryRun / -NoReload / -ConfigPath / -Summary) is the tested switch: exit 0, and a second run left runtime\config.yaml byte-identical. It never starts or stops HypoMux, validates before it stops the watcher, and rolls config + mihomo + watcher back on failure. The weights it carried came from HypoMux's own algorithm, ported and unit-tested — the suite is 404 tests now (with Invoke-RepoChecks at 9/9).
  • DNS is designed, not in force: the policy belongs to mihomo, but the live config has dns.enable: false and UDP :53 is held by ICS (the hotspot), so resolution is per adapter today. Open item, not a working resolver.
  • SQX / Dukascopy: the whole data source is proxied now (owner, 2026-10-11: "give sqx datadownload all from proxy (dispatch NIC by hypomux as always)"). DOMAIN-SUFFIX,dukascopy.com moved from LOCAL to DATA — the Dukascopy website included, which used to be direct — with the two hosts SQX actually pulls kept explicit: DOMAIN,datafeed.dukascopy.com,DATA and DOMAIN,freeserv.dukascopy.com,DATA. They target DATA and not the 4:1 mix on purpose: bulk downloads want a few stable exits (Dukascopy terminates TLS from bursty/multi-IP sources — SQX logged 1,138 of those; the free Aliyun exit answers 429), and HK alone downloaded 4/4 files cleanly. DATA = load-balance round-robin over filter: "香港|新加坡|日本|德国", health-checked on a real Dukascopy tick URL every 600 s. strategyquant.com stays LOCAL — proxying it trips Cloudflare's 403, and that is the SQX site, not its data feed. Verified: datafeed → DATA[香港|HK2022|AT], freeserv → DATA[日本|JP2021|AT] (429), www → DATA[新加坡|SG2034|AT] (302).
  • The course player is Vimeo, and Vimeo was split across two exits (2026-10-25). The tutorial page embeds player.vimeo.com/video/332228885; mihomo sent the player API through RULE-SET(autolearn-paid) to PAID while every media host (vod-adaptive-ak.vimeocdn.com, skyfire.vimeocdn.com, f.vimeocdn.com, i.vimeocdn.com) matched MATCH,DISPATCH and went direct through the phone — where TLS to the CDN failed outright, so segments never arrived. New group VIMEO = fallback [aliyun-native, LA-POOL], health-checked on https://i.vimeocdn.com/robots.txt (expected 200, 300 s, lazy: false), with DOMAIN-SUFFIX,vimeo.com,VIMEO and DOMAIN-SUFFIX,vimeocdn.com,VIMEO placed above the paid rule set: one exit for API and media, because Vimeo signs each session's URLs — TOKYO-POOL rotated exits between the config call and the playlist and answered 403. Measured on one connection: aliyun-native 1.68 MB/s (1.22 Fastly) against LA-POOL 0.51; five separate requests read only 0.44 MB/s because each paid its own TLS handshake. The same activation returned strategyquant.com from AUTO to LOCAL — proxied requests to that host get Cloudflare's interstitial (headless Chrome rendered the challenge through the proxy, the real page without), and the design record already listed the host under LOCAL. After the change, through the unmodified rules: 10/10 segments, 10.37 MB in 5.75 s, 1.81 MB/s (~14.4 Mbps), and a public Vimeo clip played to its end in headless Chrome with every host on VIMEO[aliyun-native]. Not verified: the course video is login-gated, so authenticated playback was not exercised. Evidence: docs\verification\2026-10-25.md.
  • Paid spend is no longer bounded by ordering — it is the default: the 4:1 mix sends 4 of every 5 proxied connections to the metered plan on purpose, reversing the free-first priority. The old 40 GB byte-counting guard lived in the retired watcher and went with it, so nothing counts bytes today — whether to replace it, or change the ratio, is open (docs\TODO.md P0e). The paid dials are NIC-dispatched: the provider carries override: dialer-proxy: hypomux (its old interface-name: 以太网 override removed) — measured 96 sockets in mihomo before the switch, 95 in hypomux-engine after it, mihomo 0.
  • Microsoft Store & Update: domestic CDN, pinned DISPATCH (via HypoMux, not the old raw DIRECT), ~17.8 MB/s measured.
  • PowerShell 7 is the default shell (2026-10-11): every task action is pwsh.exe (7.6.6) except the two WinRT hotspot tasks, which stay on powershell.exe — measured: PS7 cannot project the tethering types (Operation is not supported on this platform. (0x80131539)), and every caller of Hotspot.ps1 stays on 5.1 with them. The long-running mihomo-supervisor.ps1 (pid 21232) is still hosted by 5.1 until its next restart — not restarted on purpose, because it runs mihomo as a pipeline child and killing it takes the proxy down.
